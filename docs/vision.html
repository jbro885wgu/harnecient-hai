hai: what long-term use looks like toy

This runs the real hai engine (the same rules as the CLI and the demo) over a simulated month of use. The user is scripted, not a prediction of real people. Change the sliders and watch what the rules do over time.

1. The knobs

Grades: 0 bad, 1 good, 2 to 4 better. The daily cap (10) and one grade per reply are the real rules; the slider can't go past them.

5. How it works, in order

  1. Reply. A word matches a concept (the one with the most matching words wins). Ties go to the higher weight.
  2. Grade. The user grades the last reply. A grade adds reward or punish counts from rules (grade 0 = one punish, grade 1 = one reward, grade 2 to 4 = more reward).
  3. Weight. Each concept's weight is (reward+1)/(reward+punish+2). It starts at 0.5, moves up with good grades and down with bad ones, and never reaches 0 or 1.
  4. Options. When nothing matches, the bot lists the top three concepts by weight. So learning changes what it offers, not what the replies say.
  5. Limits. Replies never change, so learning cannot invent new answers. The daily cap stops one person from forcing a result in one day.
  6. Memory. Everything above is replayed from the ledger, so a restart gives the same weights.

6. What long-term use means, in three steps (the vision)

  • Now (built): a chat that learns which concepts a person finds useful, from grades, with replies fixed and checked.
  • Next (planned): a haibot: a chat agent with a party of six, a PC box, elements, faint and healing, and battles that test what it learned. Each part is a ledger row, so the same save file reloads anywhere.
  • Later (planned): tools, linked documents, observed models (with a person in the loop), and a viewer that shows progress. See the roadmap in the repo book, section 11.

The toy only shows the first step. The rest is design and is labelled as such everywhere.

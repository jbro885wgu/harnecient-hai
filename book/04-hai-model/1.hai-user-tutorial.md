# 📘 hai: user tutorial, the CLI and the window (2026-11-22)

📅 Who this is for: a person who wants to **use** hai, and see what it does.
Status legend as in `0.hai-model-architecture.md`: **BUILT**, **DESIGN**, **NOT YET**.
This tutorial only describes what runs today. Each command below was run; the builds in section 1 are the two you need first.

## 1. Before you start (BUILT)

You need: Linux, a terminal, and the hai repo (`harnecient-hai`, branch `hai`).
Nothing is installed globally yet (the installer is M7, not built).
Commands below run from the repo folder.

```
cd harnecient-hai
gcc -std=gnu11 -Wall -Wextra -O2 -I ops -o ops/hai ops/hai.c ops/hai_chat_core.c
```

That one line builds the CLI (`ops/hai`). The state command needs its own build: `gcc -std=gnu11 -Wall -Wextra -O2 -I ops -o ops/hai_chat ops/hai_chat.c ops/hai_chat_core.c`. Both are git-ignored.

## 2. Your first session in the terminal (BUILT)

Start it with a data folder and a ledger file:

```
./ops/hai chat/data my-chat.ledger
```

You see:

```
hai 0.0.0-m3
[1] Help
[2] Quit
Type a number, or words.
hai>
```

Type a word and press Enter. Examples that are known today:

| You type | hai answers with | Why |
|---|---|---|
| `hi` | "Hi. I can chat with fixed replies for now. Type help." | the `greet` concept |
| `help` or `1` | the list of what it knows | the `help` concept (1 is a word of it) |
| `account` | "What name should I use for you?" | moves the chat to asking a name |
| `bo` (after account) | "Nice to meet you, bo." | stores the name in the ledger |
| `weather` | "I don't know that yet. Did you mean: [1] … [2] … [3] …?" | no concept matched, so it offers options, not a guess |
| `bye` or `2` | "bye", and the program exits | the chat ends |

After `bye`, starting again with the same ledger says:
`The chat is closed. Start hai again to talk.` That is correct: the closed state
is in the ledger, not in the program's memory.

Piped (no typing), the same session works:

```
printf 'hi\naccount\nbo\nweather\n2\n' | ./ops/hai chat/data my-chat.ledger
```

## 3. What the ledger is, and how to look at it (BUILT)

Every line you type adds one row to `my-chat.ledger`:

```
TURN|1795349296|bo|none|r_named|idle|store_name|bo
```

Fields: time, what you typed, the concept it matched, the reply id, the state
after, the action, and the name stored. Read it with any text tool.

**Do not edit it by hand.** The program rebuilds the state from these rows every
run. A hand-edit changes behaviour without a trace (house rule: no ghost data).
To start over, use a new ledger file name.

To ask what state it is in, without typing a turn:

```
./ops/hai_chat state my-chat.ledger
state=idle name=bo
```

## 4. The window (BUILT, read-only, W0)

The window shows the same ledger. It is read-only: you watch it, you do not
type in it yet (typing in the window is NOT YET).

Start it (dev setup, from the house tree, since the renderer is built there):

```
sh window/button.sh <house_root>
```

It needs the manager built first (`window/bin/hai_manager`). The window's
manager reads `window/state/chat.ledger`. So to see your CLI session in the
window, point the window's ledger at your file, or copy the ledger into
`window/state/chat.ledger` (a copy, never the live file).

What you see (from the screenshot taken on 2026-11-22):

- **Title bar**: `hai`, with the X and _ buttons (close, minimize). The window is
  a normal house window; it also shows up in the taskbar strip.
- **Left sidebar**: the time of the last refresh, then the state line
  (`idle name=bo`), then `turns = 5`.
- **Rows** (numbered `[1]` to `[n]`): each row is one turn, shown as
  `you: <what you typed> -> <reply id>`.
- **Right panel**: a plain description, read-only.

What to check when you use it (the house's acceptance habit):
1. Type a turn in the CLI.
2. Wait about 2 seconds (the manager refreshes every 2 s).
3. The new row appears in the window. If it does not, the ledger you are reading
   is not the one you typed into. That mismatch is the most likely cause.

## 5. Taking a picture (BUILT, the house way)

The window can be captured by its ID with `xwd`, then converted to PNG with
`ffmpeg`. Open the PNG and describe what you see; do not describe a picture
you did not open. (The full-desktop screenshot came back black in our test; the
per-window capture works. The cause is not yet known.)

## 6. Limits you should know (say these before showing it to anyone)

- Replies are fixed text. It does not write new sentences.
- The options it offers are in file order, not sorted by fit yet.
- Any word becomes the name when it asks for one, including "help". A guard is owed.
- Grades (0 to 4), linked documents, weights and tool calls are not built yet
  (see `0.hai-model-architecture.md`).
- No installer yet. You run it from the repo.

## 7. Quick reference

| Want to | Do |
|---|---|
| Chat in the terminal | `./ops/hai chat/data <ledger>` |
| See the state | `./ops/hai_chat state <ledger>` |
| Start over | use a new ledger file name |
| See it on screen | `sh window/button.sh <house_root>` (after building the manager) |
| Run the checks | the harness cases `hai_account`, `hai_core`, `hai_chat` (see the repo book) |

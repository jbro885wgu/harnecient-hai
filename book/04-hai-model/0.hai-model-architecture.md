# 🧠 The hai-model: architecture (2026-11-22)

📅 Status legend, used everywhere in this folder:
**BUILT** = in the repo, with a harness name and an observed result · **DESIGN** = written down, not running · **NOT YET** = agreed, not started.

## 1. What the hai-model is (owner's words, 2026-11-22)

> "we aren't using a model. just the hai-model of learning from user."

So: **no neural network, no language model, no GPU.** The hai-model is a
**finite state machine (FSM)** plus **human-readable weights**, where every
fact it knows is a row in a text file. It learns by counting: what worked,
what did not, and what the user said. You can open every file and read it.

A learner can take in knowledge from three kinds of source:

| Source | What it gives | Trust | Status |
|---|---|---|---|
| **User input** (what you type, a name you give, a document you link) | new concept rows, reply rows, names | the user decides | typed input BUILT in the engine; document linking DESIGN |
| **User grades** (0 bad, 1 good, 2 to 4 better) | reward or punish counts on the reply you graded | a person, can be noisy | DESIGN (grade mapping written, not built) |
| **RL scores** (a harness verdict, a tool call that passed or failed) | reward or punish from a measured check | highest: measured, not asked | DESIGN (harness verdict exists; not wired to chat) |
| **Observing other models** (their output files, read as data) | candidate rows, capped weight, labelled SOURCE | lowest until a person or a harness confirms | DESIGN |
| **Distillation** (an outside model writes fixed-shape rows, we keep only the ones a harness verified) | optional extra rows | only verified rows count | DESIGN, OPTIONAL, never required |

Rule: **no source is mandatory.** The hai-model must work with user input and
RL scores alone. Distillation and observation are extra inputs, never the base.

## 3. How learning changes the model (DESIGN, the rule to hold to)

1. **Every change is a row.** A grade is a `GRADE` row. A linked document is
   `SOURCE` rows. An observed suggestion is a `CANDIDATE` row. Nothing edits a
   file in place to change behaviour.
2. **Weights are counts.** Reward and punish counts per concept or reply. The
   ratio is the weight. Nothing is trained by gradient descent.
3. **Caps stop one voice from dominating.** A user's grades count at most a set
   number per day (RULE row). A candidate from an observed model starts at a
   capped weight and must be confirmed (by a grade or a harness verdict) before
   it moves further.
4. **Options are how it asks.** When unsure, it offers options with a confidence
   number. The user's pick is the cheapest reward there is.
5. **The ledger is the memory.** Delete a projection (a view file) and it
   rebuilds identical bytes from the ledger. Hand-editing the ledger is refused
   on replay (DESIGN: the audit check, owed).

## 4. What is NOT the hai-model (say this to anyone who asks)

- Not a language model. It does not write new prose. Replies are fixed rows.
- Not a learned embedding. Matching is by words and by counts.
- Not connected to any outside service. Observing another model means reading
  its output **files**, never calling its API from a case.
- Not a finished product. Typed window input, grades, linked docs, weights and
  tool calls are still to be built. See the status column.
